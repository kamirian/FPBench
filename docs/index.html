Why Average Error Is Not Enough

Most FP evaluations report a single number — the MAE or RMSE of force magnitude across all atoms. That is convenient but incomplete.

The problem: a model can predict forces that point in the wrong direction, or produce large errors on a small fraction of atoms, and both failure modes are invisible in the average.

These failures have consequences. Static relaxations and NEB calculations typically require force convergence in the 0.001–0.01 eV/Å range. Misdirected or unusually large forces during MD can destabilize a trajectory.

Metric Definitions

Per-atom metrics, evaluated across three physically motivated force regimes.

Δ|F|
Signed force-magnitude error — eV/Å
Δ|F| = |F_FP| − |F_DFT|
Positive when the FP over-predicts force magnitude, negative when it under-predicts. Used where the sign itself is informative.
|Δ|F||
Absolute force-magnitude error — eV/Å
|Δ|F|| = | |F_FP| − |F_DFT| |
The magnitude of the error above, used for MAE/RMSE and fraction thresholds throughout this benchmark.
Δθ
Force-angle error — degrees
Δθ = arccos( F_FP · F_DFT / (|F_FP| |F_DFT|) )
How wrong is the predicted force direction? Undefined (excluded) when either |F_FP| or |F_DFT| is ~zero for that atom.
e_vec
Force-vector error — eV/Å
e_vec = ‖F_FP − F_DFT‖
A single number combining both magnitude and direction error into one Euclidean distance between the two force vectors.
r_F
Relative force-magnitude error
r_F = |Δ|F|| / |F_DFT|
Normalizes the magnitude error by the DFT reference force — useful for comparing error scale across very different force regimes.
Frac(δ & α) ↑
Joint magnitude+angle accuracy
% atoms: |Δ|F|| < δ AND Δθ < α
Requires both low magnitude error and accurate direction simultaneously — reported at (δ,α) = (0.01 eV/Å, 1°) and (0.01 eV/Å, 20°).

Zero-force exclusion

An atom's Δθ is undefined if either |F_DFT| or |F_FP| is ~zero for that atom — there is no angle to compute relative to a zero vector. Such atoms are excluded from every flattened per-atom metric array, independently per FP (a zero FP-predicted force is model-specific, so different FPs can retain slightly different atom populations — this is expected, not an inconsistency). The generator notebooks' raw per-structure checkpoint (results_*.json) retains every atom regardless, with the undefined angle stored as null. The all-atom Δ|F| MAE/RMSE sweep in the analysis notebooks is the deliberate exception, reporting on the full population including near-zero-force atoms.

Three analysis regimes

Evaluated

|F_DFT| > 0.01 eV/Å

The FDFT_MIN cutoff used throughout the analysis notebooks — excludes near-zero DFT forces, where small absolute errors can dominate a relative comparison. Applied only in analysis, never at generation time.

Non-FE

0.01 < |F_DFT| ≤ 1 eV/Å

Near-equilibrium atoms — the majority population in most datasets, and the one most likely to dilute an average error metric.

FE (far-from-equilibrium)

|F_DFT| > 1 eV/Å

Transition states, migration pathways, and rattled/strained structures. 26.9% of MatPES-PBE, 33.3% of MatPES-r2SCAN, 80.0% of OMat24 rattled-1000 (reference-model counts).

Reproduce & Extend

Everything here is runnable code, not a fixed leaderboard — see "Using FPBench with another dataset" in the README for the full walkthrough. In short:

1

Analysis only, from paired Cartesian forces

Already have DFT and FP Cartesian forces? Call build_force_results(dft_forces, fp_forces, structure_ids) directly — see the worked example in analysis/force_error_analysis_matpes_pbe.ipynb.

2

Full dataset generation

Use a notebook in generation/ as a template: chunk your dataset, register your FP (its own venv/checkpoint), generate + submit SLURM scripts, then run the strict cross-model-consistency merge into the standardized schema.

3

Configure paths for your system

Every dataset/cluster/checkpoint path is a plain, clearly-marked variable near the top of its cell. Cells raise a clear error if you run them before editing the placeholders — nothing silently uses someone else's paths.

Analysis Code

Four Python modules imported by the notebooks — dataset-agnostic, operating on the standardized force_results schema.

scripts/force_results.py

Standardization core

build_force_results(dft_forces, fp_forces, structure_ids) — the single source of truth for the standardized per-atom fields. Embedded (checksummed, byte-identical) into every generated cluster job so it needs no install there.

scripts/force_error_metrics.py

Core analysis engine

  • Fraction tables — |Δ|F||<threshold, joint with Δθ
  • Regime panels — non-FE vs. FE splits
  • Conditioned MAE/RMSE on |FDFT| or Δθ thresholds
  • Query utilities — get_bad_atom_indices
scripts/fp_cdf_density_plots.py

CDF and density visualization

  • CDF of |Δ|F||, Δθ, e_vec, non-FE / FE split
  • 2-D density heatmaps with marginal histograms
  • PCHIP-smoothed curves, automatically placed zoom insets
scripts/heatmap_table.py

Heatmap drawing primitives

The custom split-triangle heatmap style — each cell divided diagonally to encode two statistics at once (e.g. MAE vs. RMSE, or Δθ<1° vs. <20°).

  • draw_triangular_cell, triangular_heatmap_with_fraction_row
  • plot_fraction_panel
