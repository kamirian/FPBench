Metrics

FPBench evaluates phase stability and elemental ordering using metrics chosen for their direct relevance to computational materials screening workflows.

Convex hull and relative phase stability

Ground-state agreement, within-phase hull-minimum agreement, and global hull-minimum agreement test whether an FP identifies the same low-energy structures DFT does, at increasing scope (composition → phase → full tie-line system) -- directly relevant to using an FP for phase-diagram or stability screening in place of DFT.

Elemental-ordering energy ranking

Top-1 accuracy, Recall@k, and Spearman ρ test whether an FP can rank competing atomic arrangements at a fixed composition the way DFT does -- relevant to order/disorder and site-occupancy screening, where getting the relative energy ordering right matters more than the absolute energy value.

Rate of ranking errors and misranked-pair energy gap

A low average energy error can still hide a high rate of pairwise ranking mistakes. The mean/max DFT energy gap for misranked pairs distinguishes a near-degenerate mix-up (small gap) from a confidently wrong prediction (large gap).

Structural-relaxation accuracy (RMSD)

An FP that reproduces DFT energies well can still relax to a geometrically different structure. RMSD against the DFT-relaxed structure, plus the fraction of structures an FP fails to even map onto its DFT counterpart, is directly relevant to any downstream workflow (e.g. NEB, further static calculations) that consumes the FP-relaxed geometry itself, not just its energy.

These metrics are complementary and should be interpreted together rather than combined into a single overall ranking.

Notation and Protocols

Full FP relaxation currently means atomic- position relaxation with a fixed cell, using ASE FIRE, with fmax = 0.01 eV/Å and a maximum of 10,000 steps; cell shape and volume are held fixed throughout (not a variable-cell relaxation). The FP starts from the DFT initial_structure (the un-relaxed starting geometry) and must produce both its own energy and its own relaxed structure.

Static FP evaluation means evaluating the FP's energy on the corresponding DFT-relaxed structure (relaxed_structure) without relaxing it any further -- only the FP's energy is required; no separate FP structure is produced or used, and RMSD does not apply.

A candidate an FP has a result for is recorded with status: "success" and its energy_total; one it does not is "missing", "failed", or "non_converged". Only "success" records are ever scored, but the distinct label is preserved and reported separately by the validator -- a missing, failed, or non-converged result is never silently dropped or backfilled from the DFT value.

Adding a New FP to This Benchmark

FPBench's Phase Stability and Elemental Ordering component is open to additional FPs. The current set (see the model table on the FPBench home page) will grow over time; existing results stay tied to the FP version they were computed with.

The generator notebook (generation/convexhull_ordering_run_generator.ipynb) and analysis notebook (analysis/convexhull_ordering_analysis_all_models.ipynb) referenced below directly produce and consume the results reported here, with no manual conversion step between them.

Set up your FP's environment

Clone the repository and install your FP's own package in a separate environment, alongside requirements.txt. The generator notebook never installs packages automatically.

git clone https://github.com/mogroupumd/FPBench.git
cd FPBench/Phase_stability_ordering
pip install -r requirements.txt   # then install your FP's package separately

Configure and generate jobs

Edit POTENTIAL_REGISTRY for your FP (Section 2), add its key to SELECTED_POTENTIALS, then run Sections 5-7 to generate hull/ordering jobs and per-model/all-model submission scripts. _require_configured(...) raises a clear error if a placeholder path or SLURM setting is still unedited. Running these cells never submits a job by itself.

Run jobs, then merge

Run the generated scripts on your cluster, then merge completed chunks into a per-FP fragment (Section 8) and into the final standardized results file (Section 9 -- guarded by RUN_REAL_MERGE = False until you explicitly enable it and choose a merge mode).

Compute the metrics

Re-run analysis/convexhull_ordering_analysis_all_models.ipynb against the updated standardized results file to reproduce every table above with your FP included.

Reproduce & Extend

See the Phase_stability_ordering README for the full quick start, standardized-file schema, and how to call the public builder/validator/table functions with your own data.

git clone https://github.com/mogroupumd/FPBench.git
cd FPBench/Phase_stability_ordering
pip install -r requirements.txt
pip install jupyterlab
jupyter lab analysis/convexhull_ordering_analysis_all_models.ipynb

Both standardized data files (data/phase_stability_ordering_reference.json.gz, data/phase_stability_ordering_results_standardized.json.gz) are committed directly in the repository -- no separate download needed to reproduce every table above.
